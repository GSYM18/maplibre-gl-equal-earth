# Handoff: the plugin and the native blend on MapLibre 6.18.0 (start on or after 2026-11-19)

Written 2026-11-12. It supersedes `2026-11-15-maplibre-6.17-handoff.md` (kept for history; where
the two differ, this one is right). It is the single entry point for the work below and is
committed on the local branch `feature/native-blend` of this repository.

The work is split into **five stages, one fresh session each**. A session does its stage, passes
the stage's gate, fills in the progress log at the end of this file, commits, and stops. Do not
start the next stage in the same session.

## 1. Goal

A MapLibre GL JS setup that shows Mercator vector tiles (OpenMapTiles, SmartMaps) in Equal Earth
at low zoom and blends into Mercator while zooming in, as globe does. The blend must be as
unnoticeable as possible: the place under the pointer stays put, labels glide and never re-lay
out because of the projection, the map is never emptier than plain Mercator, and frame time
stays close to Mercator's.

Two deliverables reach that goal together:

- **The plugin** (this repository, `@yellowmap/maplibre-gl-equal-earth`) on stock MapLibre:
  stepped bands for adaptive `equal`, `addProjection` for pure `equal-earth`. Its stepped
  transition has a fixed ceiling (shear snaps at each band step); do not try to tune it away.
- **The fork** (`../maplibre-gl-js-equal-earth`, package `@yellowmap/maplibre-gl`): a per-vertex
  Equal Earth → Mercator blend in the renderer. It is the only route to the goal. The plugin
  detects a fork build and hands over to it, so applications keep one API.

## 5. What is known about MapLibre 6.18.0 (read from the tag's source, not run)

Line numbers are for tag `v6.18.0`; re-check each against the installed package before relying
on it. The camera section of this repository's `CLAUDE.md` describes **6.6** and is out of date.

- **`Camera#isEasing` is gone** (since 6.17). `Camera#isMoving()` (`src/ui/camera.ts:1545`)
  asks a `CameraMovementScheduler` (`src/ui/camera_movement_scheduler.ts`: `isMoving`,
  `isMovingAxis`, `isContinuedBy`, `scheduleSegment`, `interrupt`, `fireAfterQueued`).
- **The Camera's own `moveend` listener deletes the requested state `R` only while the
  scheduler is idle** (`camera.ts:454-456`). On 6.16 it always deleted it.
- **`R` is still created lazily** by `getTransformForUpdate()` when a `transformCameraUpdate`
  hook or terrain exists (`camera.ts:1095-1098`), and `applyUpdatedTransform` still runs the hook
  on it and writes the result to the rendered transform only (`camera.ts:1304-1345`).
- **The rendered transform is read-only from outside**: `private _transform`, public getter
  `transform: IReadonlyTransform` (`camera.ts:368-374`). Changes go through
  `camera.applyTransformChange(tr => …)`.
- **The HandlerManager fires `moveend` and the gesture `*end` events through the Camera**
  (`src/ui/handler_manager.ts:815`; the Map is the Camera's evented parent). On 6.6 it fired
  them on the Map. So "a Map-fired `moveend` does not reach the Camera" no longer describes
  MapLibre.
- **The inertial ease calls `this._camera.easeTo(...)`** (`handler_manager.ts:796`), not
  `this._map.easeTo`, so it does not pass through a method wrapped on the Map instance.
  `Camera#stop()` takes no argument (`camera.ts:1531`); the handler manager's `_camera` is
  private.
- **`Map`'s camera methods are one-line delegates** to `this._camera` (`src/ui/map.ts`:
  `easeTo` 1541, `jumpTo` 1481, `flyTo` 1578, `fitBounds` 1432, `cameraForBounds` 1411). Calls
  the Camera makes on itself (`fitBounds` → `easeTo`, `flyTo` → …) never reach the Map.
- **`TransformProvider` still exists** and the keyboard, scroll-zoom, tap-zoom, click-zoom and
  box-zoom handlers still hold one (`keyboard._tr` is how `geo-api.ts` finds its prototype).
- **`addProjection`** is unchanged from 6.15 in shape; 6.18 includes #8964 (no jump when dragging
  above or below a registered projection's world).
- 6.18.0 depends on `@maplibre/maplibre-gl-style-spec` `^26.6.0` (published 2026-11-09).

**What breaks in the plugin as it stands**

- `src/map/camera.ts:184-190`: `discardRequestedState` returns false when `isEasing` is not a
  function, so on 6.18 `R` is never discarded. That reopens the double conversion under banded
  `equal` (Guadalajara 1.74° off).
- `src/map/camera.ts:489` and `:569` read `isEasing()` to tell an ease frame from a gesture
  frame; both get `undefined` on 6.18.
- **Banded `equal` has only ever been browser-tested on 6.6.** The 6.16 Playwright project runs
  `native.spec.ts` alone, where the camera is the identity. Treat every camera rule in
  `CLAUDE.md` as a hypothesis to re-derive, not as fact.
- `src/map/geo-api.ts` decides per value whether a camera target is map space. Its audit
  (`docs/superpowers/audits/2026-10-11-geo-api-audit.md`) assumed MapLibre's internal calls reach
  the wrappers; on 6.18 the inertial ease and the Camera's own chains do not.
- `src/map/constrain.ts:214-215` and `geo-api.ts:317-319` read `map._camera.transform`; that
  still works for reading.

## 7. Gotchas

- Windows; many files are CRLF. Use the Edit tool or scripts that preserve line endings. Inline
  heredoc Python sometimes fails in this shell: write scripts to the session scratchpad.
- `python3` is the Windows Store stub and hangs; use `python -I`.
- Installing local git hooks was blocked once by the permission system; do not retry.
- Never write `in <word> <word>` in a shader prelude comment: MapLibre's `prepare()` reads it as
  a vertex attribute.
- Do not edit anything under `src/` or `demo/` while `npm run probe:transition` runs.
- The npm tarball of MapLibre has no `test/` folder; render tests need the git clone.
- EPSG:8857 is ellipsoidal and the plugin's CRS is spherical: up to ≈ 0.128° apart. Do not mix.
- `git filter-branch` over a range (`v5.24.0..branch`) is how the fork's messages were rewritten;
  `git filter-repo` would also rewrite the shallow root.
